2. 整批发布新dist内容及对应镜像配置，不能只替换index.html或部分JS。发布平台的所有目标端口与探测端口同步改29876。
3. 从可访问服务的环境读取 `/sub/plsm/plsm-release.json`，再读取 `http://10.151.255.167:18090/sub/plsm/plsm-release.json`，确认两处buildId相同，并与本次内网dist文件一致。若直连为新版而18090为旧版，优先检查入口路由和代理缓存。

5. 页面成功加载后才检查权限、查询等后端请求；刷新功能路径应正常回到PLSM入口，缺失JS应返回404而不是HTML。

## 发布平台的Dockerfile配置

镜像构建上下文填当前前端工程根目录，Dockerfile路径填根目录的 `Dockerfile`，构建产物为上一步生成的dist。流水线镜像阶段必须依赖编译阶段成功，不能用旧产物继续打镜像。Dockerfile的关键内容如下，与仓库文件保持一致：

```dockerfile
FROM swr.ckgf-global-1.cccar.com.cn/work_place/nginx:1.23-alpine
COPY dist/ /usr/share/nginx/html/sub/plsm/
COPY deploy/nginx.release.conf /etc/nginx/nginx.conf
EXPOSE 29876
CMD ["nginx", "-g", "daemon off;"]
```

不要照搬其他项目把dist复制到html根目录。本项目PUBLIC_PATH和history回退均为/sub/plsm/。镜像直接使用完整nginx.release.conf，不引用基础镜像默认conf.d配置；Nginx实际监听29876，发布单也只映射29876。基础镜像可能继承EXPOSE 80元数据，但这不等于启动80监听或对外映射80。

如果发布平台另外挂载了nginx.conf，挂载内容仍会覆盖镜像内文件，因此也必须替换为本次完整配置。仅修改Dockerfile里的EXPOSE不会改变Nginx实际监听端口。

现场入口代理、发布平台配置与缓存尚未由本机修改；本次源码交付不能等同于内网路由或接口联调通过。
