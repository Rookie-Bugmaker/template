# PLSM前端发布单端口冲突处理（2026-11-12）

日志报错为：`services "svc-workplace-plsm-front" is forbidden: protocol_port 19091 ... already has been usesd by other service`。失败发生在发布平台创建服务、分配负载均衡监听端口时，还不能据此判断Nginx配置、静态文件或前端代码运行有问题。重复发布不会释放其他服务已经占用的端口。

用户已确认发布平台支持“集群内访问”，本次采用该方式，取消前端服务对负载均衡19091的绑定。原主平台入口仍为 `http://10.151.255.167:18090/sub/plsm/`。

## 发布单字段

| 字段 | 填写内容 |
|---|---|
| 应用 | workplace-plsm-front |
| 服务访问方式 | 集群内访问 / ClusterIP |
| 服务协议 | TCP |
| 服务端口 / port | 80 |
| 容器端口 / targetPort | 80 |
| 负载均衡器及对外监听端口 | 取消选择，不再填19091，不另占18090 |
| Nginx监听 | listen 80 |
| 完整nginx.conf的容器内部路径 | /etc/nginx/nginx.conf |
| 静态文件目录 | /usr/share/nginx/html/sub/plsm/ |

若发布平台将服务端口和容器端口合并为一个字段，填写80即可。若它只支持上传server块，该块应挂载到 `/etc/nginx/conf.d/default.conf`；包含worker_processes/events/http的完整配置才挂载到 `/etc/nginx/nginx.conf`，两种结构不能混放。

不需要修改 `.env` 中开发服务器的18091、PUBLIC_PATH或PLSM服务前缀；这些值不会解决负载均衡端口占用。也不要直接把负载均衡端口改成80，80是本次ClusterIP服务及容器的端口。

## 原18090入口转发

ClusterIP不提供外部直连入口。现有18090入口必须能访问集群内部Service，并配置 `/sub/plsm/` 转发到前端服务的80端口，转发时保留完整路径；既有主平台 `/` 和 `/api` 路由继续使用原配置。

转发目标以发布平台显示的实际集群内地址为准。日志中的服务名为 `svc-workplace-plsm-front`，完整域名通常为 `svc-workplace-plsm-front.<实际命名空间>.svc.cluster.local`；命名空间与集群DNS后缀须核对，不能把环境标识或应用名猜作命名空间。以下只是路由模板，必须先替换占位地址，再合并到原18090的server块：

```nginx
location = /sub/plsm {
    return 301 /sub/plsm/;
}

location /sub/plsm/ {
    # 将占位地址替换为入口可访问的真实服务地址；无结尾斜杠，保留/sub/plsm/路径。
    proxy_pass http://PLSM_FRONT_SERVICE_ADDRESS:80;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

如果18090入口部署在集群外且不能访问ClusterIP/内部DNS，应通过集群Ingress接入现有入口，或由运维提供可达路径；不能直接填内部域名后认为已经可用。只有无法通过既有入口访问集群服务时，才另行申请确实空闲的负载均衡监听端口，并同步入口上游地址；不要删掉占用19091的其他业务服务。

1. 保存发布单后重新部署，确认Service类型为ClusterIP，port/targetPort均为80，且有就绪的后端端点。
2. 从18090入口所在环境验证能访问实际Service的 `/sub/plsm/index.html`；内部访问成功后再测试外部入口。
