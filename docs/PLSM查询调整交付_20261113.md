# PLSM 查询调整交付

本次以用户已部署的前端 `14552c7`、后端 `9d8be5e` 为基线，增加实车可选筛选、固定关键列、调整四表历史查询及状态颜色。前端源码在plsm分支，内网合并到对应test分支构建。

## 功能和接口变化

- 实车查询增加“车辆号”和“主物料号”，均非必填、精确匹配。车辆号请求字段vehicleNo对应三表vehicle_no；主物料号请求字段hmatnr对应一表h_matnr，即原“主件物料”列，不是行物料号matnr。编码按字符串保留前导零，留空不限制；车型、车组编号仍必填。
- 实车表前三列依次为序列号、物料号、物料名称，均固定左侧。操作列继续固定右侧，其他列横向滚动。
- 两个页面共用的历史弹窗仅传serialNumber、pageNo、pageSize给GET `/plsm/history`。后端只按序列号精确查询第四表全部未删除历史，覆盖不同物料、空物料号及全部租户。有序列号即可查看历史，无序列号仍禁用。弹窗增加每条历史物料号列；顶部制造信息仅代表当前选中记录，不代表其他物料的档案。
- 规划、位置及档案的生效状态1显示绿色，失效状态0显示红色；实车状态0上车为绿色，1下车、2作废为红色。未知或未提供状态用灰色。四表历史状态没有重新定义，继续显示原值。
- 分页、导出仍使用已提交的查询条件快照。档案唯一键和SMART/SRM档案接口仍为“序列号＋物料号”，没有改成仅序列号。

## 合并与部署

1. 先合并并发布后端增量，后端不再要求历史matnr参数，兼容旧前端多传该参数；新条件已纳入分页及导出。

4. 已部署的查询免登录、全租户范围以及管理员写入限制继续沿用。
